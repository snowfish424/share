二、學員開始前必須完成
1. 統一使用 Linux / Bash 練習主機，已安裝 Podman、oc、Python 3、curl。
   Windows/macOS 學員建議 SSH 至指定 Linux 主機；課中不處理 VM 或跨架構安裝。
   確認 Podman 可執行，Containerfile 的 RUN 能在 ARCH 指定架構執行。
2. 每位學員一個獨立 Project，例如 cwa-user01；同一 Project 僅放一份本範例。
   已依該學員的身分完成 oc login，並具建立本課應用、Route 與 PVC 的權限。
   Pod/資源配額至少容納 1 個 Pod、CPU request 100m、memory request 128Mi、
   limit CPU 200m / memory 256Mi、1Gi PVC，以及 ConfigMap/Service/Route。
3. 本次推送及部署統一使用 quay.io/cwa/ocp/cwa-weather:1.0。
   cwa 為 Quay Namespace／組織，ocp/cwa-weather 為含巢狀路徑的 Repository。
   請先在 Quay 確認此 Repository 已建立、帳號可存取，並核對 Public / Private。
   練習主機及 OCP 節點可連線 quay.io；基底映像與 PyPI 套件可下載。
   Registry、套件來源、Route 的 DNS、CA 與網路已確認。
   本課固定使用 1.0 Tag，部署設定為 imagePullPolicy: Always，建立 Pod 時核對最新映像。
4. 提供具有該 Quay Repository Write 權限的帳號或 Robot Account。
   Robot 使用者名稱格式為 namespace+robotname，實際名稱由講師配發。
   密碼或 Token 僅在 Password 提示時輸入，不寫入 env、指令檔或 PDF。
   全班使用固定 1.0 Tag；若修改程式，由講師安排推送順序，避免覆寫彼此版本。
5. 已建立應用 ServiceAccount cwa-app。Public Repository 可直接拉取；
   Private Repository 須預先設定 quay.io 的 imagePullSecret 並連結至 cwa-app。
   OCP 建議使用只有 Read 權限的獨立 Quay Robot；本機推送使用 Write 身分。
   本課部署檔使用 cwa-app，並停用 Pod 的 API Token 自動掛載。
6. 有可用的預設 StorageClass，支援本課 1Gi / ReadWriteOnce PVC，容量足夠。
   render.py 會使用預設 StorageClass；若需指定類別，講師先調整並預演。
   WaitForFirstConsumer 模式可能在 Pod 建立前顯示 PVC Pending，請等部署排程。
7. 為每位學員複製 quickstart.env.example 為 quickstart.env，填妥 PROJECT、
   REGISTRY_USER、ARCH、BASE_IMAGE；YOUR_QUAY_USERNAME 必須換成實際登入名稱。
   REGISTRY 固定 quay.io，PUSH_IMAGE 與 DEPLOY_IMAGE 使用相同的指定完整位址。
   將各自的 quickstart.env 放在學員的 workshop/；其中不放任何 Token。
8. 講師使用與學員相同的登入權限，依五步手順走完一次，確認最後 HTTPS 回應成功。
   演練時選擇另一個獨立 Project，學員課程從乾淨的 Project / PVC 開始。
   不要直接覆寫已有重要資料的同名 PVC 或應用。

三、講師快速核對（在 workshop/，載入對應學員設定後）
以下只列檢查用指令，帳號及叢集管理準備由講師完成。

source quickstart.env
oc whoami
oc project "$PROJECT"
oc -n "$PROJECT" get serviceaccount cwa-app
oc -n "$PROJECT" get serviceaccount cwa-app \
  -o jsonpath='{.imagePullSecrets[*].name}'
oc get storageclass
bash scripts/preflight.sh --local
podman login --get-login quay.io

Private Repository 拉取認證（講師課前執行；Public 可略過認證步驟）：
先設定 QUAY_PULL_USER 為具有 Read 權限的 Quay 使用者或 Robot 名稱，
再執行以下區塊，於 Password 提示輸入其 Token。勿使用含其他 Registry 的認證檔。

mkdir -p .secrets
chmod 700 .secrets
podman login --authfile .secrets/quay-pull.json \
  --username "$QUAY_PULL_USER" quay.io
chmod 600 .secrets/quay-pull.json
oc -n "$PROJECT" apply -f k8s/serviceaccount.yaml
oc -n "$PROJECT" create secret generic registry-pull \
  --type=kubernetes.io/dockerconfigjson \
  --from-file=.dockerconfigjson=.secrets/quay-pull.json \
  --dry-run=client -o yaml | oc -n "$PROJECT" apply -f -
oc -n "$PROJECT" secrets link cwa-app registry-pull --for=pull

Public Repository 仍須先建立 cwa-app（oc apply 上述 serviceaccount.yaml）。
原完整講義的 Registry 與 ocp-integrated-registry.txt 保留作其他環境參考。
檢查清單不等於部署驗收，仍須以實際學員權限走過完整手順。

五、錯誤協助（保留學員所在步驟，先確認 PROJECT）
oc -n "$PROJECT" get pods -l app=cwa-weather
oc -n "$PROJECT" get pvc cwa-weather-data
oc -n "$PROJECT" get events --sort-by=.lastTimestamp
oc -n "$PROJECT" describe deployment cwa-weather
oc -n "$PROJECT" logs deployment/cwa-weather -c api --tail=80
oc -n "$PROJECT" get route cwa-weather

ImagePullBackOff：核對 Quay 映像位址、1.0 Tag、Private 權限與 cwa-app 拉取認證。
Pending / PVC Pending：檢查 Events、StorageClass、供應狀態、配額與排程。
CrashLoopBackOff：先看 logs，再檢查應用程式入口與掛載目錄權限。
Route 503：先確認 Pod Ready，再看 Service selector、EndpointSlice 及目標埠。
推送認證失敗：核對 Quay 登入帳號、Token 與該 Repository 的 Write 權限。
需要 Pod 詳細事件時，使用 oc -n "$PROJECT" describe pod 加上實際 Pod 名稱。
